# Project Name

GO / NO-GO (GNG)

# Summary *

GO / NO-GO (GNG) is an interactive, browser-based spacecraft mission design, systems-engineering verification, and orbital operations simulator. Across six sequential stages—Mission Briefing, Spacecraft Architecture, Orbit & Launch, Engineering Verification, Mission Operations, and Mission Debrief—users engineer complete spacecraft for deep-space missions (`LUNAR SCOUT`, `MARS OBSERVER`, and `ASTEROID EXPLORER`) across `STANDARD`, `HARD`, and `EXPERT` difficulty levels.

Powered by a standalone SI-unit aerospace engineering engine, every hardware, payload, orbit, and launcher choice propagates across coupled mass, power/battery DoD, Tsiolkovsky propulsion/ODAR, 1-node thermal equilibrium, RF link/SSR data backlog, cost, and NPR 8705.4B reliability models. Following the core principle **"The system advises. The user decides."**, the Stage 4 Flight Readiness Review provides an advisory `ENG: GO` / `CAUTION` / `NO-GO` assessment while allowing the Mission Director to make the final `GO — Authorize Launch` or `NO-GO — Hold Launch` decision (with explicit risk acknowledgement if overriding an engineering `NO-GO`). Authorized missions run through a full-viewport 5-phase cinematic launch sequence into an automatic, deterministic 60-second fixed-timestep 3D orbital simulation, culminating in a `35/25/15/15/10` normalized debrief score, optional Earth-observation/weather reference provenance (Planetary Computer, NASA GIBS, Meteomatics), and an optional Supabase-backed International Leaderboard (`PROVISIONAL` standings).

# Project Details *

### What GO / NO-GO Does & Problem Solved
Spacecraft engineering is a tightly coupled trade-study discipline where changing one subsystem cascades across mass, power, thermal, communications, propulsion, cost, and reliability. GO / NO-GO turns these coupled trade-offs into an inspectable six-stage engineering and operations experience in the browser:

1. **Stage 1 — Mission Briefing (`/`)**: Starts on an Earth-first 3D viewport with the Moon in the background and an interactive destination view toggle. Choose between `LUNAR SCOUT` (default), `MARS OBSERVER`, and `ASTEROID EXPLORER`, select `STANDARD` / `HARD` / `EXPERT` difficulty, or load baseline `GO` / `NO-GO` presets. Includes optional native `<dialog>` Earth-observation and weather reference panels for terrestrial calibration context.
2. **Stage 2 — Spacecraft Architecture (`/architecture`)**: Assemble 3 buses, 16 subsystems (Solar, Battery, Antenna, Propulsion, Thermal, Avionics), and 7 scientific instruments using layered engineering planning sheets (`PlanningSheetDiagram`) and educational thin-slice glass selection cards explaining what each component does, why it matters, advantages/limitations, compatibility, and NASA learning links.
3. **Stage 3 — Orbit & Launch (`/orbit`)**: Configure circular or elliptical orbits (perigee, apogee, eccentricity, inclination, analytical $J_2$ Sun-Synchronous inclination) and pair the spacecraft with 4 launch vehicles while inspecting live orbital geometry, ground-station visibility, and `<TechTerm>` aerospace abbreviations.
4. **Stage 4 — Engineering Verification (`/verification`)**: Inspect 8 coupled engineering domains, 7 NASA Concept Maturity Level (CML 1–6) readiness gates, 10 structured `ValidationFinding` checks, and the `MissionAdvisorPanel`. Make the final **GO — Authorize Launch** or **NO-GO — Hold Launch** decision (with risk acknowledgement confirmation if overriding `NO-GO`) to trigger the full-screen 5-phase launch sequence.
5. **Stage 5 — Mission Operations (`/operations`)**: Enters directly into an automatic frame-rate-independent fixed-timestep (`60 s`) 3D orbital simulation (`1x`–`1000x` speed, `+6h`/`+24h` fast-forward) with deterministic anomaly mitigation and an optional collapsible `Advanced Controls` drawer for manual payload toggles, duty-cycle modes, downlink bursts, orbit trim burns, safe mode, and heater overrides.
6. **Stage 6 — Mission Debrief (`/debrief`)**: Review the normalized `100`-point score (`35` Science, `25` Reliability, `15` Resource Efficiency, `15` Data & Comms, `10` Risk Management), compare engineering assessment vs. director authorization, scrub the telemetry replay timeline, inspect equations via the Formula Inspector (`PHYSICAL_LAW`, `ENGINEERING_APPROXIMATION`, `GAMEPLAY_RULE`), and optionally submit results to the International Leaderboard.

### Tech Stack & Architecture
- **Frontend & 3D**: React 19, TypeScript, React Router, Vite 8, Tailwind CSS v4, Zustand v5, Recharts, Lucide React, Three.js (`@react-three/fiber`, `@react-three/drei`) with `SceneCanvasGuard` WebGL fallback.
- **Engineering & Simulation Engine (`Go-No-Go/src/engine/`)**: Pure TypeScript SI-unit modules verified by `vitest` (`9` suites, `65` unit & integration tests passing), Playwright (`4` E2E tests passing), `oxlint` (`0` warnings/errors across `83` files), and `tsc -b --noEmit` (`0` errors).
- **External Supporting Context**: Client-side Microsoft Planetary Computer STAC/Data APIs and NASA EOSDIS GIBS WMTS tiles, plus a server-side `/api/weather` Cloudflare Pages Function (`functions/api/weather.ts`) proxying Meteomatics Weather API over a 4-basin allowlist with 30-minute caching and secret scrubbing.
- **Optional Leaderboard Backend**: Supabase PostgreSQL 17 with RLS and `SECURITY DEFINER` RPCs (`submit_verified_mission_score`, `get_mission_leaderboard`) that validate physical bounds, recompute `35/25/15/15/10` scores server-side, record browser runs honestly as `PROVISIONAL` (`is_verified = false`), and fall back cleanly to an offline state when unconfigured.
