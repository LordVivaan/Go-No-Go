# Go-No-Go — Workspace Survey & Reference Guide

**Go-No-Go** is a web-based space mission design, simulation, operations, and readiness-review ("Go / No-Go") platform. For the application-level overview, tech stack, and target directory structure, see [`Go-No-Go/README.md`](file:///workspaces/Go-No-Go/Go-No-Go/README.md).

This root `README.md` documents **every tool, dataset, 3D model, PDF, ontology, configuration, and source directory** across the workspace and explains how each contributes to the platform.

## 4. Aerospace Standards, PDFs, Ontologies & Reference Implementations (`/Resources`)

The [`Resources/`](file:///workspaces/Go-No-Go/Resources) directory grounds **Go-No-Go** in NASA standards, systems engineering frameworks, and open-source 3D orbital visualization code.

2. [`13-3547_A1b.pdf`](file:///workspaces/Go-No-Go/Resources/13-3547_A1b.pdf) — *Space Mission Concept Development Using Concept Maturity Levels* (JPL, 2013): Defines **CML 1–9**, the **24-row CML Matrix**, and **CML 2–6 Red/Yellow/Green (RYG) Checklists** for `src/engine/validation.js` and `scoring.js`.

4. 7. [`SE-Curriculum-Intro.2021-09-20.pdf`](file:///workspaces/Go-No-Go/Resources/SE-Curriculum-Intro.2021-09-20.pdf) — *Systems Engineering Curriculum* (NASA SE Handbook Rev 2): Covers the **17-process SE Engine** and cost/risk/performance/schedule trade-study mechanics.

## 6. Independent Engineering Verification & Scientific Integrations

### SI Engineering Engine Audit & Limitations
All calculations inside [`Go-No-Go/src/engine/`](file:///workspaces/Go-No-Go/Go-No-Go/src/engine) use internal SI units (`kg`, `m`, `s`, `m/s`, `W`, `J`, `N`, `K`, `Hz`, `bits`/`bytes`) with explicit UI display conversions:
- **Verified Physical Constants ([`constants.ts`](file:///workspaces/Go-No-Go/Go-No-Go/src/engine/constants.ts))**: IAU 2015 Resolution B3 solar constant ($G_0 = 1361.0\ \text{W/m}^2$ at $1\ \text{AU}$), WGS-84 / EGM2008 Earth parameters ($\mu = 3.986004418\times 10^{14}\ \text{m}^3/\text{s}^2$, $R_E = 6378.137\ \text{km}$, $J_2 = 1.08262668\times 10^{-3}$, $\omega_E = 7.2921150\times 10^{-5}\ \text{rad/s}$), CODATA 2018 Stefan-Boltzmann constant ($\sigma = 5.670374419\times 10^{-8}\ \text{W m}^{-2}\text{ K}^{-4}$), JPL DE440 lunar/Martian $\mu$, and OSIRIS-REx reference asteroid parameters.
- **Astrodynamics ([`orbital.ts`](file:///workspaces/Go-No-Go/Go-No-Go/src/engine/orbital.ts))**: Two-body vis-viva velocity, safeguarded Newton-Raphson + bisection Kepler solver (validated up to $e = 0.9999$), secular $J_2$ Sun-Synchronous inclination/precession ($\le 0.05^\circ/\text{day}$ tolerance around Earth $+0.9856^\circ/\text{day}$), and GEO comparison against Earth's sidereal day ($86164.09\ \text{s}$). *Limitation: educational two-body + secular $J_2$ model only; excludes atmospheric drag, solar radiation pressure, and third-body perturbations; not for flight-certified trajectory design.*
- **Power & Battery ([`power.ts`](file:///workspaces/Go-No-Go/Go-No-Go/src/engine/power.ts))**: Inverse-square irradiance scaling $(1\ \text{AU}/r)^2$, true $\max(0, \cos\theta)$ incidence attenuation, distinct average vs. simultaneous peak load checks against array output + battery 1C discharge limit, and energy balance in Joules / Watt-hours with charging/discharging efficiencies and a minimum $20\%$ safe operational State of Charge threshold during eclipse simulation.
- **Data & RF Communications ([`data.ts`](file:///workspaces/Go-No-Go/Go-No-Go/src/engine/data.ts), [`communications.ts`](file:///workspaces/Go-No-Go/Go-No-Go/src/engine/communications.ts))**: Explicit instrument duty-cycle data generation and compression ratio, bounded SSR ring-buffer overflow tracking, RF-band-filtered ground passes ($0$ passes when no ground station matches the antenna band), consistent link equation ($EIRP$, FSPL, atmospheric + pointing/line losses, $(G/T)_{rx}$, $E_b/N_0$ margin), and AWGN Shannon-Hartley capacity explicitly labeled as a theoretical upper bound rather than an operational rate.
- **Propulsion, Thermal, Reliability & Scoring ([`propulsion.ts`](file:///workspaces/Go-No-Go/Go-No-Go/src/engine/propulsion.ts), [`thermal.ts`](file:///workspaces/Go-No-Go/Go-No-Go/src/engine/thermal.ts), [`reliability.ts`](file:///workspaces/Go-No-Go/Go-No-Go/src/engine/reliability.ts), [`scoring.ts`](file:///workspaces/Go-No-Go/Go-No-Go/src/engine/scoring.ts))**: Non-mutating Tsiolkovsky rocket equation with thrust/burn-duration/propellant checks, simplified 1-node radiative thermal equilibrium (clearly labeled *not* a multi-node spacecraft thermal design analysis), distinct series-chain vs. parallel-redundant avionics constant-hazard-rate reliability models, deterministic rule-based Mission Advisor ([`advisor.ts`](file:///workspaces/Go-No-Go/Go-No-Go/src/engine/advisor.ts)) with fail-closed optional server-side narrative hook, and reproducible $35/25/15/15/10$ mission scoring that awards $0$ science points with $0$ instruments and never rewards over-budget hardware.
- **Data Provenance**: Spacecraft hardware & instruments in [`components.ts`](file:///workspaces/Go-No-Go/Go-No-Go/src/data/components.ts) and [`instruments.ts`](file:///workspaces/Go-No-Go/Go-No-Go/src/data/instruments.ts) explicitly carry `provenance` metadata (`ILLUSTRATIVE`, `VERIFIED_SPEC`, `EDUCATIONAL_MODEL`, `GAME_RULE`) rendered directly in the Spacecraft Builder cards.

- [`nasaDataService.ts`](file:///workspaces/Go-No-Go/Go-No-Go/src/services/nasaDataService.ts), [`planetaryComputerService.ts`](file:///workspaces/Go-No-Go/Go-No-Go/src/services/planetaryComputerService.ts), and [`NasaEarthObservationPanel.tsx`](file:///workspaces/Go-No-Go/Go-No-Go/src/components/NasaEarthObservationPanel.tsx) integrate official NASA EOSDIS GIBS WMTS EPSG:3857 tiles (`MODIS_Terra_CorrectedReflectance_TrueColor`, `VIIRS_SNPP_CorrectedReflectance_TrueColor`) and Microsoft Planetary Computer STAC & Data APIs (`sentinel-1-rtc`, `sentinel-2-l2a`, `cop-dem-glo-30`) over `FLOODWATCH` river basins.
- Includes automated bounding box queries, short-lived SAS token acquisition in transient memory, 256px WebMercatorQuad tile resolution with rendered preview fallback, explicit provenance tracking (`getRecordedEoDatasetUsage`), and transparent offline fallbacks with clear data attribution.

### Meteomatics Weather Integration & Security Boundary
- [`functions/api/weather.ts`](file:///workspaces/Go-No-Go/Go-No-Go/functions/api/weather.ts) and [`meteomaticsWeatherHandler.ts`](file:///workspaces/Go-No-Go/Go-No-Go/src/server/meteomaticsWeatherHandler.ts) implement an authenticated server-side Cloudflare Pages Function proxy and local Vite dev proxy (`/api/weather`) that communicates directly with Meteomatics Weather API.
- All credentials (`METEOMATICS_USERNAME`, `METEOMATICS_PASSWORD`) remain strictly server-side (stored in Cloudflare environment variables or `.dev.vars`, never in browser code or client bundles).
- Queries are strictly allowlisted to the 4 FLOODWATCH basins and 3 time windows (`current`, `forecast_24h`, `historical_24h`), with client and server caching, provenance metadata recording (`getRecordedWeatherUsage`), and graceful offline fallback to scenario monsoon baselines when unconfigured.
